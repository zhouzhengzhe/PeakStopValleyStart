# 测试方案（usage-info-bar）

> 沿用本项目既有约定：**无测试框架、无依赖**，`node test/x.test.mjs`，全部确定性（注入固定时钟与固定时区），断言中文可读。

## 分层原则

**正确性全部压在纯函数层**（阶段 1）。IO 层（host 采集、余额、槽位注册）只做契约与结局断言。这样绝大多数 bug 会在毫秒级的纯函数测试里被抓住，而不是等到跑起来看栏。

---

## T1 · 价格折算

| 用例 | 判据 |
|---|---|
| 四类 token 各自单价正确 | 手算值逐一相等 |
| 空闲价 = 高峰价 × 50% | 对每个模型成立 |
| 缓存命中输入 ≪ 未缓存输入 | 单价关系正确（防顺序写反） |
| 未知模型 | 进"未定价"桶，**不产生金额** |
| 零 token | 金额 0，不进桶 |

## T2 · 峰谷定档（最容易错，重点覆盖）

| 用例 | 判据 |
|---|---|
| 工作日 09:00:00 / 08:59:59 / 12:00:00 / 11:59:59 | 各自落在正确档 |
| 工作日 14:00 / 18:00 边界同上 | 半开区间，不与 T1 冲突 |
| 周六、周日全天 | **全部空闲**（BR-3） |
| 跨界调用（08:59 发起、09:01 结束） | **整笔归发起档**（BR-4）——用结束时刻定档必须让它失败 |
| 时区无关性 | 同一 UTC 瞬间，无论进程时区如何，档位相同 |

## T3 · 聚合不变量

| 用例 | 判据 |
|---|---|
| `峰 + 谷 ≡ 总` | 对每一时间窗成立 |
| 本会话 ⊂ 今日 ⊂ 近一月 ⊂ 全部 | 单调包含 |
| 跨日边界（本地 23:59 → 00:01） | 正确落入不同"今日" |
| 跨月边界 | "近一月"窗口正确 |
| 空账本 | 全 0，不抛错 |

## T4 · 采集契约（`llm/stream` 四种结局）

| 用例 | 判据 |
|---|---|
| 正常完成 | **恰好一条账** |
| 多个 usage chunk | 只取最后一个（快照语义），**不是累加** |
| 上游 `next()` 抛错 | 不记账，**异常继续上抛** |
| 流中途中断 | 记一条且标 `interrupted` |
| 无 usage chunk | 不记账，不抛 |
| chunk 透传 | 输入 N 个 chunk，输出 N 个，顺序与内容不变 |

> 「多 usage chunk 只算一次」和「异常继续上抛」是两条必须存在的断言：前者防重复计费，后者防把上游故障消化成静默。

## T5 · 余额降级

| 用例 | 判据 |
|---|---|
| 首次成功 | 显示数值 |
| 之后失败 | **保留上次成功值 + 失败标记**（不是空白、不是 0） |
| 无凭据 | 明确提示，不静默 |
| 401 / 超时 | 文案可区分 |
| 密钥泄漏 | 断言其**不出现在**任何前端载荷与日志里 |

## T6 · 槽位契约

| 用例 | 判据 |
|---|---|
| 注册的 id | 是自有 id，**断言它不等于 `'stats'`** |
| `slots` 晚就绪 | 会等待；超时后有告警而非静默 |
| 卸载第三方插件后 | 官方行仍在 + 我们的行出现 |

> 「断言 id ≠ 'stats'」是本方案里性价比最高的一条：它把"并存两行"这个用户决定钉成回归测试，防止将来有人"顺手"改成接管。

## T7 · 回归

- 既有全部断言（当前 382 条）保持全绿。
- 特别确认：刹车语义、徽章、面板、设置页、命令**零回归**。
- 新增测试不得引入网络、不得依赖真实时钟、不得写真实文件。

## 手工验收清单（跑完自动测试之后）

1. 输入框下方出现**两行**：官方统计 + 我们的信息栏。
2. 我们的行显示：服务商+模型、余额、当前档位、距空闲倒计时、本会话花费。
3. 悬停"本会话花费"→ 今日 / 近一月 / 全部，且**峰谷拆分之和等于总额**。
4. 跨一次峰谷切换（可临时改时钟或用测试账号验证）→ 档位与倒计时同步翻转，已记的账不回流。
5. 拔网线 → 余额保留旧值 + 失败标记，不空白。
6. 重启 DSH → 今日/近一月/全部 的账仍在。
7. 以上全部通过**之后**，才卸载 `dsh-bottom-info-bar`，再复核 1–6。
