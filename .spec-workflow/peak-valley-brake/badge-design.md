# 鲸鱼娘徽章：功能设计

- 状态：待评审
- 依赖：host 侧的会话投影已实现并在真实宿主验证通过（`lib/hold-state.js`，commit `dd22c0c`）
- 素材：`鲸鱼娘_透明背景_1..4.png`（1122×1402，透明背景）

## 1. 为什么是徽章，而不是对话消息

这是本项目最容易搞错的一点，先说清楚。

**当前状态**：刹车拦截时尝试用 `agent.inject()` 发一条"回执"。探针证明这**不是消息，而是"待处理上下文"**——被拒的步骤会丢弃它，而且它**从不进入会话日志**。所以它时有时无、回看找不到。操作者要么盯着宿主终端看日志，要么得想到去敲 `/peak-valley status`。

**徽章的价值**：常驻、可见、**零模型成本**。它读的是会话事件折叠出的投影，不唤醒模型，不产生 token。

## 2. 四个形象 ↔ 四种状态

四张图恰好构成一组完整的状态表达，直接用作四态：

| 图 | 姿态 | 状态 | 副标题 | 何时显示 |
|---|---|---|---|---|
| **2** 眨眼比 V | 活泼、正常 | **谷时正常** | 未拦截 | `phase = open`，`engaged = false` |
| **3** 手指轻触下巴 | 思考、预备 | **峰前预警** | 还有 N 分钟 | `phase = armed`（峰前 5 分钟） |
| **1** 伸手向前 | 正在工作/挡 | **峰时拦截中** | 已拦截 N 条 | `engaged = true` |
| **4** 抱着小鲸鱼 | 交付、满足 | **放行交付** | 已放行，继续 | `lastReleaseReason` 刚更新（短暂 4s） |

**状态优先级**（同一时刻只能显示一个）：

```
放行交付（4s 内） > 拦截中 > 峰前预警 > 谷时正常
```

## 3. 徽章主体

- **位置**：默认右下角，可拖拽；位置存 `localStorage`，**跨会话记住**
- **贴边自动翻转**：拖到左半屏时库/气泡朝右展开，避免被裁切
- **缩放**：默认 96px 高；挤压窗口时降为 64px；用户可在设置里选 迷你/标准/大
- **待机动效**：轻微上下浮动（3s 循环），幅度极小，不干扰阅读
- **状态切换动效**：淡入淡出换图（200ms），避免突兀闪跳
- **计数变化**：气泡数字弹一下（scale 1 → 1.15 → 1）

## 4. 悬停工具条（命令行的可视化）

鼠标移到形象上浮现。**每个按钮都是斜杠命令的等价物**——不是新增能力，只是把已有命令做成按钮。

| 按钮 | 等价命令 | 何时可点 | 说明 |
|---|---|---|---|
| **状态** | `/peak-valley status` | 始终 | 展开详情卡（同命令文本） |
| **放行一次** | `/peak-valley now` | 仅拦截中 | 放一次；**下一条仍会被拦** |
| **放行到谷时** | `/peak-valley window` | `phase ≠ open` | 持续放行到下一个调度边界 |
| **撤销覆盖** | `/peak-valley cancel` | 有覆盖生效时 | 调度重新接管 |
| **气泡开关** | — | 始终 | 关掉/打开头顶气泡 |

**不可点时置灰并给 tooltip 原因**（例如"当前是谷时，无需放行"）。这样按钮本身就是状态说明的一部分。

**危险提示**：`放行到谷时` 会按峰价持续计费，所以按钮上带一个 `¥` 角标，点击后气泡里给一句确认文案再执行——不弹模态框（打断太大），而是让图标短暂变色并显示"已按峰价放行"。

## 5. 头顶气泡

- **默认显示**：被拦截时自动展开，让"为什么没反应"一眼可见
- **可关闭**：气泡右上角 ×，关闭后**记住**（存 `localStorage`）；形象头顶保留一个小圆点提示，避免彻底失联
- **可重开**：工具条的气泡开关，或点形象本身
- **内容**：

```
┌───────────────────────┐
│ 已拦截 2 条       × │
│ 18:01 自动放行       │
│ 悬停看操作            │
└───────────────────────┘
```

- **谷时**：气泡不显示（没有要报告的事），除非用户强制常显
- **峰前预警**：显示"还有 3 分钟进入峰时"

## 6. 我建议补充的功能（你没提但值得考虑）

按价值排序，前三个我建议做进第一版：

1. **成本累计**——气泡第二行显示"本次峰时已省 ≈¥0.42"（按拦截条数与平均 token 估算）。这是插件存在的理由，把它显示出来最有说服力。**需要标注是估算值**。
2. **倒计时**——"距谷时 2:14:33"实时走秒，让人知道还要等多久。
3. **点击穿透到会话**——详情卡里点"查看滞留消息"能看到被扣消息的摘要（台账里已有 `summary`），确认自己没丢东西。
4. **一键跳转到该会话**——如果你开了多个会话，徽章可以列出"其他会话也被拦截了 N 条"，点击切换。
5. **主题跟随**——用 `--dsw-*` 变量，亮/暗主题下都好看（官方原语已提供）。
6. **首次使用引导**——第一次出现时气泡里写"把我拖到顺手的位置"，之后不再提示。

**建议不做**：自定义形象上传（增加素材管理复杂度，收益低）、音效提醒（后台常驻时很烦）。

## 7. 技术方案（已核实）

### 数据方向：客户端 ← 宿主

用**已实现的会话投影**（`peakValleyBrake`）。客户端订阅后，切换会话会**自动显示那个会话自己的状态**——因为投影本就是按会话折叠的。

### 资源方向：形象图片

四张 1122×1402 的 PNG 不能直接塞进 client bundle（会把它撑到几 MB）。已压缩入库：`assets/mascot/{128,200,320}/<state>.png`，**6.26 MB → 0.58 MB**（128 规格四张仅约 74 KB）。

**关键修正：设计初稿打算用 `ctx.webServer` 注册路由提供图片，这是错的。**

`dsh-host-webserver` 的文档写得很明确：

> 它只服务浏览器；**Electron 通过 `file://` 加载 dist**，并经 IPC 桥接承载 fetch。

而 DSH Desktop 正是 Electron。所以 webServer 路由在桌面端**可能不可达**，徽章会裂图——一个我恰好无法在浏览器里验证的故障。

**改用 data URI 内联**：把 128 规格的 PNG base64 后嵌进 client bundle。

| | webServer 路由 | **data URI 内联** |
|---|---|---|
| 浏览器 | 可用 | 可用 |
| Electron 桌面端 | **可能不可达** | 可用 |
| 依赖 | webServer 路由 + 路径约定 | 无 |
| 代价 | — | bundle 增大约 99 KB（懒加载，可接受） |

由 `scripts/embed-mascot.ps1` 生成 `lib/mascot-data.js`（不改图就不需要重新生成）。这同时让 client bundle 自包含——不依赖任何宿主路由，也少一个失败点。

### 动作方向：客户端 → 宿主（已实测确认）

**实测结论**（不是推断）：

| 问题 | 答案 | 依据 |
|---|---|---|
| DSH Desktop 的 GUI 怎么加载？ | **HTTP**，不是 `file://` | 主进程 `await window.loadURL(rendererUrl)`，且显式判断 `127.0.0.1`/`localhost`/`::1` |
| `globalThis.__DSH_TRANSPORT__` 相关吗？ | **不相关** | 全盘搜索只有读取方、无注入点；它只服务 `file://` 模式 |
| webServer 路由可用吗？ | **可用** | HTTP 页面下同源 `fetch` 本就通 |
| 端点该放哪个前缀？ | **必须在 `/api` 之下** | `/api` 是宿主唯一持有并负责认证与 Host/Origin 校验的前缀 |

**权威写法**（取自已装插件 `dsh-session-log-export` 的真实代码）：

```js
const inject = ["commands", "connection"];
connectionOf(ctx).fetch.register({
  path: '/api/session.export',        // 必须以 /api 开头
  methods: ['GET', 'HEAD'],
  requestBody: 'buffered',
  fetch: async (request) => new Response(...),
});
```

宿主的唯一 `/api` route 先做认证与信任校验，再分发给按精确路径注册的功能插件；**未认领的请求返回 404**。

因此徽章的动作端点定为 **`/api/peak-valley-brake.action`**（沿用同一点号风格）。handler 直接调用已有的 `commandHandler`，**按钮与命令行是同一个函数**，语义不可能偏离。

`connection` 声明为**可选**依赖并做容错探测：`file://` 部署与 headless 组合没有它，此时插件仍须正常守卫，只是徽章按钮不可用。

**教训**：设计初稿写的是"用 `ctx.webServer` 注册 `/plugins/.../mascot/...` 提供图片"，并认为动作端点要"另寻通道"。两处都基于对部署形态的猜测。实测把两者都纠正了——图片改为 data URI 内联（两种模式都对），动作端点走 `/api` 下的精确路由（宿主统一认证）。

## 8. 需要你确认的取舍

| 项 | 我的建议 | 理由 |
|---|---|---|
| 成本估算显示 | **做**，但明确标注"估算" | 这是插件的卖点；但精确计费需要知识库价格表与 token 归属，属于另一个模块 |
| 放行到谷时的确认方式 | 图标变色 + 气泡提示，**不弹模态** | 模态框打断太重；但需要用户能回退，所以带 `撤销覆盖` 按钮 |
| 气泡默认 | **拦截时自动展开** | 解决"看着像卡住"这个原始痛点 |
| 第一版范围 | 四态 + 拖拽 + 5 按钮 + 气泡 | 其余 3 项（成本/穿越/多会话）放第二版 |
